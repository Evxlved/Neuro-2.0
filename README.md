# RAG: база знаний по играм

Ассистент перед ответом ищет релевантные статьи в локальной базе и подмешивает их в
промпт, поэтому советы по Minecraft (и любой другой игре) берутся из статей, а не из
памяти модели.

## Как это работает

```
data/<игра>/*.md|txt  ->  чанки  ->  эмбеддинги  ->  rag_store/<игра>/
вопрос из микрофона   ->  эмбеддинг -> косинусное сходство -> top_k чанков -> в system prompt
```

Никаких внешних сервисов: индекс — это numpy-матрица (`vectors.npy`) плюс текст чанков
(`docs.jsonl`). На 50 страницах вики это 1344 чанка, 22 МБ и поиск за ~10 мс.

## 1. Положить тексты

Файлы кладутся по папке на игру, формат — markdown или обычный текст:

```
data/
  minecraft/
    Diamond.md
    Nether Portal.md
  wow/
    ...
```

Для Minecraft можно накачать вики штатным скриптом (страницы на английском):

```
python fetch_wiki.py
```

Свои заметки и гайды на русском просто кидаются в `data/minecraft/` — можно писать в
формате `# Заголовок` или `== Раздел ==`, чанкер по ним режет текст и подписывает разделы.

## 2. Собрать индекс

```
python build_index.py                # все игры из data/
python build_index.py --game minecraft
python build_index.py --list         # что уже собрано
```

## 3. Запустить main.py

Индекс поднимется сам. Голосовые команды:

- «обнови базу знаний» / «пересобери память» — пересобрать индекс из `data/`
  (идёт в фоне ~18 минут, ассистент продолжает отвечать по старой базе)
- «что в базе знаний» / «размер базы» — сколько чанков и какие игры

## Эмбеддеры: что выбрать

Три бэкенда, задаются в `main.py` (`RAG_BACKEND`) или флагом `--backend` у билдера.

| Бэкенд | Что это | Когда брать |
|---|---|---|
| `sentence-transformers` | `BAAI/bge-m3` на CPU, 2.2 ГБ | По умолчанию. Лучшее качество, **кросс-языково**: русский вопрос находит английскую статью |
| `hash-ngram` | Лексический поиск на numpy, ничего не качает | Если модель не скачалась. Сопоставляет **формы слов**, база должна быть на русском |
| `llama.cpp` | Второй `llama-server --embedding` с GGUF-моделью | Если не хочешь лишние питоновские зависимости |

**Важно:** если база английская (как `fetch_wiki.py`), а вопросы русские — нужен
`sentence-transformers` или `llama.cpp`. Лексический поиск такие вопросы не найдёт.

### Про размер чанков и лимит токенов

У каждой модели есть лимит токенов, и всё, что не влезло, **молча отбрасывается**.
Это самая коварная ошибка в RAG: индекс собирается, поиск работает, но модель
видит только начало текста.

| Модель | Лимит | Безопасный размер чанка |
|---|---|---|
| `bge-m3` | 8192 токена | до ~2000 символов |
| `multilingual-MiniLM` | 128 токенов | до ~450 символов |

Сейчас стоит `CHUNK_CHARS = 600` (в `rag_module.py`). При смене модели сборка
предупредит в логе, если чанки не влезают.

### Про время индексации

`bge-m3` на CPU считает медленно: **~18 минут** на 50 страниц вики (1283 чанка).
Это разовая операция. Запросы после сборки — ~200 мс.

Если время критично, есть `multilingual-MiniLM`: индексация ~1 минута, но качество
заметно ниже (Recall@4 около 60% против 85% у bge-m3). Скачать:

```
python download_model.py --repo sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 --out models/multilingual-MiniLM
```

и поставить в `main.py`:
```python
RAG_EMBED_MODEL = str(current_dir / "models" / "multilingual-MiniLM")
```

### Если модель не скачивается

Иногда до CDN HuggingFace не пробиться (обрыв соединения на середине файла). Тогда
качаем в обход штатного загрузчика:

```
python download_model.py                    # bge-m3 по умолчанию
python download_model.py --repo <имя> --out models/<папка>
```

Он кладёт файлы в `models/<папка>/` и печатает, что поставить в `main.py`.
После этого индекс нужно пересобрать: `python build_index.py`.

Если семантическая модель недоступна, `main.py` сам переключится на `hash-ngram` и
напишет об этом в лог — ассистент продолжит работать, просто хуже понимая вопросы.

Прогрев эмбеддера идёт в фоне, поэтому старт не виснет, пока HF пытается отдать
модель. Первые несколько вопросов после запуска могут быть без базы — как только
эмбеддер поднимется, в логе появится `RAG: эмбеддер готов`.


## Настройки

Всё в начале `main.py`:

```python
RAG_ENABLED = True           # False — выключить базу совсем
RAG_BACKEND = "sentence-transformers"
RAG_EMBED_MODEL = str(current_dir / "models" / "bge-m3")
RAG_TOP_K = 4                # сколько чанков класть в промпт
RAG_MIN_SCORE = None         # порог сходства; None — подобрать под бэкенд
RAG_MAX_CONTEXT_CHARS = 2400 # потолок объёма материалов
```

Если ассистент тащит в ответ мусор — подними `RAG_MIN_SCORE` (для семантики это
0.45–0.55). Если молчит и отвечает «не знаю» — опусти.

Материалы в промпте занимают место в контексте, поэтому при большом `RAG_TOP_K`
увеличь `-c` у `llama-server` (сейчас в инструкции стоит 4096).
